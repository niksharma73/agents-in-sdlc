エージェントモードで GitHub Copilot を使うと、コードベースを調査し、変更を提案し、ファイルを編集し、コマンドを実行します。この作業は自分のマシンでリアルタイムに実行されるため、VS Code の Copilot Chat では、ツール呼び出しやファイル編集を進行中に確認できます。差分をインラインでレビューし、個々の変更を採用または取り消し、追加のプロンプトでエージェントに指示して作業を調整または拡張できます。エディターを離れる必要はありません。

この演習では、次の内容を学習します。

- アクセシビリティエージェントの作業をリアルタイムで監視する。
- 提案されたファイル編集をレビューして採用する。
- 作業中のセッションにライトモードの切り替えを追加するよう指示する。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタムエージェントは、ハイコントラストモードを実装しています。作業中、デザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードの切り替えも追加してほしいとのことです。新しい会話を最初から始めずに、既存のセッションに追加の作業を依頼します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが実行する各手順が表示されます。調査したファイル、実行したコマンド、提案した編集を確認できます。ファイル編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールして各ツールの操作を確認します。ファイルの読み取り、編集、実行を求めるターミナルコマンドなどが表示されます。
3. エージェントがファイルを編集すると、差分がチャット内に表示されます。
   - 変更を採用するには **Keep** を選択します。
   - 変更を戻してエージェントに再度作業させるには **Undo** を選択します。
4. チャット上部の **Files changed** 表示を開くと、このセッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ターミナルコマンドの実行などで許可が必要な場合、エージェントは一時停止し **Allow** を表示します。内容を確認し、実行してもよいコマンドのみ許可してください。

5. エージェントがハイコントラストモードの実装を完了するまで待ちます。最後に変更内容の要約が表示されます。

## エージェントにライトモードを追加するよう依頼する

ハイコントラストモードができたら、同じ会話でライトモードの切り替えを追加します。同じチャットセッションを続けると、エージェントは前の作業で変更したコンポーネント、スタイルの方針、local storage の使い方をコンテキストとして保持できます。

1. Copilot Chat の入力欄に、次のフォローアッププロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントは既存の変更を調べ、ライトモードの追加を提案します。
3. 新しい編集を確認し、各差分で **Keep** または **Undo** を選択します。
4. エージェントが望まない方針 (たとえば、好みに合わない方法でトグル UI をリファクタリングするなど) に進んだ場合は、チャット入力欄の横にある **Stop** ボタンで停止し、追加の説明を送ります。

> [!TIP]
> 進行中のセッションに指示を出すほうが、最初からやり直すより短時間で済みます。フォローアッププロンプトで調整を依頼できます。「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使う」、方向を修正できます。「3 つ目のトグルを追加せず、既存の設定パネルにライトモードを組み込む」、範囲を広げることもできます。「両方の切り替えにキーボードショートカットも追加する」などと依頼します。

## 変更されたファイルを確認する

コミットする前に、エージェントが変更したすべての内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントのアクセシビリティ指針 (ARIA 属性、キーボード操作、セマンティック HTML、local storage による保存など) が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更を stage してコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードで、進行中のセッションを監視して方向付けました。ファイル編集ごとにレビューし、変更を採用または取り消し、コンテキストを失わずにフォローアップを送って作業を拡張しました。

このレッスンでは、次の内容を学習しました。

- エージェントの作業をリアルタイムで監視する。
- 個々のファイル編集を採用または取り消す。
- フォローアッププロンプトで作業中のセッションを方向付ける。

次は[次のレッスン][next-lesson]で、アクセシビリティの変更をプルリクエストとして公開し、このハンズオンでローカルのカスタムエージェントが作成した変更をレビューします。
